# campus/ — 캠퍼스 에이전트 개발 안내

캠퍼스 에이전트(폰 앱 + 캠퍼스 서버)를 만드는 곳입니다. **이 팀이 만드는 코드는 전부 이 폴더 안에** 둡니다.
`campus/` 밖은 원본 WE-Meet 의 학사 에이전트라 이 저장소에서 고치지 않습니다 → [저장소 소개의 '구분하는 법'](../.github/README.md#구분하는-법-규칙-5개)

무엇을 만드는지는 [기능 정의서](docs/캠퍼스에이전트_기능정의서_CA1_CA4.md)가 기준입니다. 결정 표는 아직 **제안**이고, 팀 회의에서 확정한 것은 정의서에 날짜와 함께 고쳐 적습니다.

## 기술 스택 (제안)

| 부분 | 쓰는 것 |
|---|---|
| 서버 | Python 3.12 · FastAPI · 1차 SQLite → PostgreSQL(+pgvector) ⏳ · 스케줄러(날씨 1시간마다 등) |
| 앱 | Next.js(App Router) 정적 export + PWA(서비스 워커 · Web Push · 위치) — 동적 라우트 대신 쿼리 파라미터(`/meal?place=`) |
| LLM | OpenAI 호환 `chat/completions` — 환경변수 `LLM_MAIN_BASE_URL` · `LLM_MAIN_API_KEY` · `LLM_MAIN_MODEL` (학사 앱과 같은 이름), 임베딩 `LLM_EMBED_*` ⏳. 모델은 AI 담당이 정한다 |
| 테스트 | 기능 폴더마다 `tests/` + pytest, 앱은 타입 검사·린트 |

## 코드 규칙

1. **폴더 이름**은 `CA번호_이름_agent` — 학사 쪽 `F1_Bachelor_agent` 와 같은 규칙.
2. **학사 폴더를 import 하지 않는다.** 학사 정보는 오늘 맥락으로만 받는다. 캠퍼스 기능끼리는 서버 API 와 `shared/schema` 계약으로 잇는다.
3. **계산기는 하나.** 시간 계산·순위 같은 계산은 서버의 한 함수에만 두고, 식사 화면과 에이전트 대화가 같은 함수를 부른다. LLM 은 문장 → 조건, 이유 한 줄, 근거를 읽고 답하기만 한다.
4. **API 경로는 `/v1/…`.** 정의서의 API 표를 따른다. 바꾸면 정의서도 같이 고친다.
5. **비밀 값은 `.env`** (커밋 금지) — 키가 필요한 폴더에는 값이 빈 `.env.example` 을 둔다. 키는 서버에만 있고 앱에는 넣지 않는다.
6. **수집 규칙**: robots 규칙이 막은 학교 사이트(`www.jnu.ac.kr` · `hakstd.jnu.ac.kr` · `lib.jnu.ac.kr`)는 자동 수집하지 않는다 — 사람이 정리하거나 기관 허락을 받는다. **카카오 로컬 API 응답은 저장·로그하지 않는다**(실시간 호출만 허용). 식당 목록의 바탕은 공공데이터 상가(상권)정보 + 팀 현장 조사다.
7. **개인정보**: 이름·학번·성적·학교 로그인 정보는 받지 않는다. 위치·취향·대화 기록은 폰에 저장하고, 서버는 요청을 처리할 때만 쓰고 로그에 남기지 않는다(요청 로그는 경로·응답 코드·소요 시간만).
8. **계산 규칙은 단위 테스트로 고정한다** — 정의서의 예시 값(예: 필요 시간 48분)이 그대로 테스트가 된다.
