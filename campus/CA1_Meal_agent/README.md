# CA1_Meal_agent — 공강 맞춤 식사 추천

담당: AI·데이터 1 · 정의서: [CA1](../docs/캠퍼스에이전트_기능정의서_CA1_CA2.md#ca1--공강-맞춤-식사-추천)

이번 공강에 **다녀올 수 있는** 식당·학식을 공강 길이 · 다음 강의실 · 예산 · 날씨 · 취향으로 골라 3곳 추천합니다.

## 모듈 계획

| 모듈 | 하는 일 | 정의서 |
|---|---|---|
| `places` | 상가(상권)정보에서 음식 업종 추출 → `Place`, 팀 조사 속성 `PlaceAttr`, 학식 메뉴 | 4-나 · 7절 |
| `timing` | 식사 공강 계산 · 필요 시간 · 적합/빠듯/제외 판정 | 4-가 · 4-다 · 5절 |
| `ranking` | 규칙 점수 · 반드시 빼는 조건 · 다양성 · 이유 칩 | 4-라 · 5절 |
| `query` | 문장 → `MealQuery`(LLM + 스키마 검증), 실패 시 규칙 파서, 되묻기 | 4-마 · 6절 |
| `taste` | 취향 갱신 규칙(1차 지수이동평균) — 앱이 같은 규칙으로 폰에서 갱신 | 4-바 · 5절 |
| `api` | `/v1/meal/recommend` · `parse` · `explain` · `places` · `cafeteria` · `feedback` · `report` | 8절 |

## 지키는 선

- `/v1/meal/recommend` 가 **유일한 계산기**다 — 식사 화면과 CA2 대화(`recommend_meal`)가 같은 함수를 부른다.
- 카카오 로컬 API 응답은 저장하지 않는다. 지도 링크는 카카오맵 검색 주소로 연다.
- 속성(가격대 · 영업시간 등)이 없는 곳은 추천하지 않는다.

## 테스트

```bash
pip install pytest
pytest campus/CA1_Meal_agent
```

`meal/` 은 표준 라이브러리만 쓴다(아직 외부 의존성 없음).

## 식당 후보 만들기

1. [공공데이터포털](https://www.data.go.kr)에서 **소상공인시장진흥공단_상가(상권)정보** 파일 데이터를 받아 **광주광역시** CSV 를 꺼낸다(이용허락범위 확인).
2. `campus/CA1_Meal_agent/data/raw/` 에 둔다 — `data/` 는 커밋되지 않는다.
3. 실행 (`campus/CA1_Meal_agent` 에서)
   ```bash
   python -m meal.places data/raw/<광주 파일>.csv
   ```
   - `data/places.candidates.json` — 반경 안 음식점 후보(종류·식사 유형은 업종에서 **추정**)
   - `data/survey.csv` — 현장 조사 양식(가까운 순, 엑셀에서 바로 열림). 가격대 · 혼밥 · 좌석 · 영업시간 · 브레이크 · 휴무 · 대표 메뉴 · 확인일을 채운다
     - 기본은 **캠퍼스 경계에서 50m 안 · 카페 제외**(2026-09 원천 기준 115곳, 캠퍼스 안 8곳 포함). 넓히려면 `--survey-within 100`, 전부는 `--survey-within 0`, 카페도 넣으려면 `--survey-cafe`
     - **다시 돌려도 채운 칸은 지워지지 않는다** — 이미 채운 줄은 범위 밖이 되거나 원천에서 사라져도 그대로 남는다
   - 분기마다 새 파일로 다시 돌릴 때 `--prev data/places.candidates.json`(지난 결과를 다른 이름으로 옮겨 두고) → `closed.suspect.json` 에 사라진 곳 = 폐업 의심
4. 캠퍼스 경계·반경은 [`directory/campus.json`](directory/campus.json) — **OpenStreetMap 의 '전남대학교' 영역(way 105125653) 경계에서 1.2km**(정의서 D1). 경계 안은 거리 0, 구역 이름은 문에서 400m 안이면 `서문 쪽`, 아니면 `캠퍼스 북동쪽` 처럼 방향.
   - 문(`anchors`): **정문**(용봉로, OSM '전남대정문') · **후문**(스포츠센터 앞, OSM '전남대후문' 승강장) · **쪽문**(알촌 옆, 설죽로214번길 쪽 경계 위 출입구) · **서문**(OSM '전남대학교 서문'). 정문·후문·쪽문 위치는 팀원 확인(2026-11-13). 다른 문을 확인하면 추가한다.
   - © OpenStreetMap contributors (ODbL) — 경계를 화면·지도에 쓸 때 출처를 표기한다.

- 주점·구내식당은 빼고, 학식은 따로 다룬다(CA1-R12). 업종 → 종류 규칙은 `meal/places.py` 의 `RULES`.
- 카카오·네이버 지도·배달앱은 수집하지 않는다(코드 규칙 6, CA1-R14).

## 처음 할 일

1. ✅ `timing` — 정의서 5절 식 + 단위 테스트(예시: 공강 100분 → 필요 48분 · 적합 · 여유 52분) → [`meal/timing.py`](meal/timing.py)
   - 정의서에 없어 정한 것(팀 확인 필요): 첫 블록 **앞**은 식사 공강으로 잡지 않는다(등교 전일 수 있음 → 직접 입력) · 마지막 블록 **뒤**는 식사 시간대 안쪽만 쓴다(예: 15:00 끝 → `17:00~19:30`) · 피크 대기는 **도착 시각**으로 판정한다 · 겹치는 블록은 합치고 출발 건물은 늦게 끝나는 블록 것
2. ✅ 식당 후보 목록 + 현장 조사 양식 → [`meal/places.py`](meal/places.py) (아래 '식당 후보 만들기')
3. 요청 문장 평가셋 50개 시작(정답 `MealQuery` 포함)
4. ✅ `ranking` — 반드시 빼는 조건 · 규칙 점수(5절 가중치) · 상위 3 다양성 · 이유 칩 · 빠듯/학식 따로 → [`meal/ranking.py`](meal/ranking.py) 의 `recommend()`
   - 정의서에 없어 정한 것(팀 확인 필요): 영업 여부는 **도착부터 식사 끝까지** 브레이크·마감에 걸리지 않는지로 본다 · 이유 칩은 **같은 요청의 다른 후보 평균보다 나은 요소**부터(그냥 기여 순이면 여유·예산이 늘 차지함) · 시험기간 보너스는 식사 15분 이하 유형(분식·학식·카페) · 혼밥 칸이 **비어 있으면 빼지 않는다**(`X` 만 뺀다, `혼밥 OK` 칩은 `O` 일 때만 — 2026-11-12)
   - 조사 속성(가격대·영업시간)이 들어와야 실제 식당이 추천된다 — 아래 '조사 결과 넣기'
5. ✅ 채운 조사 양식 읽기 · 검사 · 추천 시험 → [`meal/survey.py`](meal/survey.py)
6. ✅ 추천 화면 미리보기(개발용) → `python -m meal.preview` 후 http://127.0.0.1:8765 — 공강·요일·출발 문·다음 건물·예산·인원·먹고 싶은 종류(여러 개, 안 고르면 전부)를 바꿔 가며 카드(CA1-S03)·빠듯·학식을 본다. 식당은 한 장씩 보여 주고(왼쪽으로 밀거나 `별로예요, 다음 →` · → 키로 다음), 옆 지도(OSM 길·건물로 그린 아이콘 없는 지도)에 출발·식당·다음 건물 위치를 같이 띄운다. `여기 갈게` 는 고른 가게와 메뉴만 보여 준다. 내 PC 에서만 열리고 요청 로그를 남기지 않는다(외부에서 받는 것은 Leaflet 스크립트뿐). 진짜 앱 화면은 `campus/mobile`(프론트엔드) 몫

## 길 기준 도보 · 건물 고르기

```bash
python -m meal.walkgraph fetch       # OSM Overpass 에서 캠퍼스 주변 길(약 3.7MB) → data/osm/walk.raw.json (커밋 안 됨)
python -m meal.walkgraph buildings   # OSM 대학 건물 → directory/buildings.json (커밋됨, 102곳)
```

- 길 데이터가 있으면 도보 = ⌈길을 따라 잰 거리 ÷ 70m/분⌉(우회 계수 없음), 없으면 지금처럼 직선 × 1.3. `recommend(..., router=WalkGraph.meters)` 로 넘긴다
- 출발·도착 점은 가장 가까운 길 위 점에 붙이고, 끊긴 길 조각은 버린다(가장 큰 덩어리만). 고속도로·공사 중·출입 금지(`access=private`, `foot=no`) 길은 뺀다
- `directory/buildings.json` 은 정의서 **건물 마스터**(데이터·인프라 담당, `/v1/buildings`)가 나오기 전까지 쓰는 임시본이다. 이름은 OSM 표기 그대로(`공과대 7호관`), 건물 코드(`공7`)는 아직 없다
- © OpenStreetMap contributors (ODbL 1.0) — 화면에 출처를 표기한다
- 미리보기 바탕 지도는 **아이콘 없는 지도 하나**다(고르는 칸 없음). OSM 타일 지도는 가게·카페 아이콘이 그려져 있어 추천 별표가 묻히므로, OSM 길·건물 모양·녹지·물만 직접 그린다
  ```bash
  python -m meal.basemap fetch   # 건물·녹지·물(약 4.8MB) → data/osm/base.raw.json (커밋 안 됨)
  python -m meal.basemap build   # 길 + 위 파일 → data/osm/basemap.json (약 1.6MB, 화면이 받는 파일)
  ```
  파일이 없으면 지도 바탕이 비고 별표·길만 나온다

## 시간표로 공강 찾기

univ_us 의 F3 출결이 이미 시간표를 갖고 있으므로 CA1 은 입력 화면을 따로 만들지 않고 그 **오늘 수업**(`GET /api/attendance/today` 의 `classes`)을 받는다 → [`meal/schedule.py`](meal/schedule.py)

- `slots_from_classes(classes, buildings)` — 휴강(`state=canceled`)은 빼고 `timing.find_meal_slots` 로 식사 공강을 찾는다. 출발 = 앞 수업 건물, 도착 = 다음 수업 건물(그날 마지막이면 없음)
- 강의실 `공7-223` → 건물: ① [`directory/room_codes.json`](directory/room_codes.json)(사람이 확인한 것) ② 건물 이름에서 만든 코드(`공과대 7호관` → `공7`, `자연과학대학 1호관` → `자1` — **추정, 팀 확인 필요**) ③ 강의실 글자에 건물 이름이 그대로 있으면 그 건물. 못 찾으면 화면이 고르게 둔다. 정의서 '건물 마스터'가 나오면 바꾼다
- 미리보기: 맨 위 `오늘 시간표로 공강 찾기` — UnivUs 출결 데이터가 있으면 **고른 요일(이번 주)** 수업을 자동으로 채우고(찾는 곳: `F3_DATA_DIR` → `F3_Attendance_agent/data` → `desktop/.dev-data` → 설치한 앱 `%LOCALAPPDATA%\kr.univus.desktop\data`, 앱과 같은 규칙 `C0_Platform_agent/osenv`. fastapi 없이 F3 `store`·`service` 를 바로 읽는다), 없으면 한 줄에 `09:00-10:15 공7-223 운영체제`(휴강이면 끝에 `휴강`)로 적는다. 공강을 누르면 시작·길이·출발·다음 건물이 채워지고 바로 추천한다
- univ_us 식사 화면에 붙이는 것은 univ_us 담당과 정한다(아직 메뉴 없음)

## 조사 결과 넣기

`data/survey.csv` 를 채운 뒤 (`campus/CA1_Meal_agent` 에서)

```bash
python -m meal.survey data/survey.csv
```

추천 가능 · 아직 조사 안 함 · **고칠 줄**(줄 번호와 이유)을 알려 준다. 실제로 추천해 보려면

```bash
python -m meal.survey data/survey.csv --try 11:30 90 --weekday 2
```

(수요일 11:30 부터 90분 공강, 캠퍼스 기준점에서 출발·도착. `--budget 8000` · `--party 5` 도 된다)

| 칸 | 적는 법 |
|---|---|
| 가격대 | `A`(≤7천) · `B`(7천~1만) · `C`(1만~1.5만) · `D`(>1.5만) |
| 혼밥 | `O` / `X` (`가능` · `불가` 도 됨) |
| 좌석 | `S`(≈10석 이하) · `M` · `L` |
| 영업시간 | `월-금 11:00-21:00 / 토 11:00-15:00` · `매일 10:30~22:00` · 요일 없으면 매일 · 새벽 영업은 자정에서 끊음 · 못 찾았으면 `영업시간 확인 필요` → 하루 종일 연 것으로 두고(휴무·브레이크는 뺌) 카드에 `영업시간 확인 필요` 칩, 마감 시각은 비움 (2026-11-13 팀 결정 — 정의서 CA1-R11 '속성 없으면 추천 안 함'의 예외) |
| 브레이크 | `15:00-17:00` (모든 날) · `토 14:00-17:00` |
| 라스트오더 | `14:30 20:00`(점심·저녁 구간마다) · `월-금 13:50 / 토 22:40` · 비우면 마감 시각만 본다. 도착이 그 구간의 라스트오더보다 늦으면 '주문 마감'으로 뺀다 · 자정 넘은 라스트오더(`00:40`)는 무시 |
| 휴무 | `일` · `월,화` · `없음` |
| 영업 상태 | `폐업` · `못 찾음` · `제외`(팀이 뺀 곳) 이면 뺀다 |
| 종류·식사 유형(확인) | 비우면 추정값을 쓴다 |

- 엑셀에서 그냥 'CSV' 로 저장해도(CP949) 읽는다. 좌표는 `data/places.candidates.json` 에서 id 로 찾으니 **id 칸은 지우지 않는다**.
